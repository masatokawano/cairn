# Personal Health Observatory

> 自分の身体について、何が測定され、何を行い、どのように変化し、
> 何を根拠にどう理解しているかを、長期にわたり検証可能な形で保持する。

## 1. 位置づけ

Personal Health Observatory（PHO）は、Cairnに健康領域を追加する提案である。
一般的な「健康管理アプリ」ではなく、次のものを統合する**個人観測・研究基盤**として扱う。

- 血液検査や健診値
- Apple Healthに蓄積された時系列データ
- 家庭血圧、体重、体温など
- 服薬・サプリ・禁煙・運動・飲酒などの介入イベント
- 内視鏡、画像検査、診療記録、検査票などの原本
- 医師の説明、本人のメモ、AIによる分析
- ZoteroやKarakeepに保存した医学的根拠

## 2. 中核原則

### 2.1 測定値と解釈を混ぜない

「ある検査値がX.Xであった」は観測事実である。
「その指標は安定している」は解釈である。
両者を同じレコードやMarkdown本文に混在させず、解釈から参照した観測値へ遡れるようにする。

### 2.2 原本を保存し、正規化値は再生成可能にする

検査票画像、PDF、Apple Health export、CSVなどの原本は改変しない。
正規化された観測値、集計、グラフ、AI要約は派生物として再構築可能にする。

### 2.3 健康データをCairnの全文検索DBへ大量投入しない

心拍数、歩数、睡眠ステージなどの大量サンプルは専用の分析ストアで扱う。
Cairn本体へ登録するのは、ソースの存在、重要イベント、期間集計、生成レポート、
原本への参照だけとする。

### 2.4 AIは観測者・整理者であり、診断者ではない

AI出力は常に「解釈」として記録し、モデル、作成日時、参照データ、プロンプト版、
確信度、置換関係を保存する。診断や薬剤変更を自動確定しない。

### 2.5 公開コードと私的データを物理的に分離する

Cairnリポジトリにはコード、スキーマ、文書、合成テストデータだけを置く。
実データはGit管理外のローカルディレクトリに置き、パス、バックアップ、権限を明示する。

## 3. 期待する利用体験

次の問いに、原データと根拠へ遡りながら答えられる状態を目標とする。

- 薬を開始する前後で、対象指標と安全性指標はどう変化したか。
- 最近半年の血圧、体重、睡眠、運動量に同時変化があるか。
- 健診値の変化は単発の測定条件か、持続的な傾向か。
- 次回受診時に医師へ伝えるべき変化と質問は何か。
- 過去のAI分析のうち、後の検査で支持・修正・否定されたものは何か。
- 現在不足しているデータは何か。

## 4. MVPの範囲

最初の価値は「全部を取り込むこと」ではなく、以下を同じ時間軸へ置くことで得る。

1. Google Sheets由来の血液検査
2. Apple Health exportの主要指標
3. 服薬・サプリ・生活介入イベント
4. 原本ファイルの所在とハッシュ
5. 再現可能なMarkdownレポート

初期対象のApple Health指標は、歩数、安静時心拍数、心拍変動、睡眠、体重、
血圧、運動時間に限定する。全HealthKit型への一般化は後続フェーズとする。

## 5. 非目標

- 疾患の自動診断
- 薬剤の開始・中止・用量変更の自動提案
- 異常値だけを強調する不安喚起型通知
- Apple Health全サンプルのembedding
- AI解釈を原本や医師記録として扱うこと
- 健康データの無制限なクラウド複製
- FHIR完全準拠をMVPの条件にすること
- 医療機関向け電子カルテを作ること
