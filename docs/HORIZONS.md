## 0. 前提 — 外部脳は「記憶装置」ではない

Cairn の本質はアーカイブでも検索エンジンでもなく、**理解が時間の中でどう変化したかを
検証可能に保つ器官**である（NORTH_STAR §1）。この定義から出発すると、発展の方向は
「もっと多く貯める」ではなく「**時間をもっと上手に扱う**」に向かう。

人間は時間の扱いが構造的に下手である。過去を物語に圧縮し、信じていたことを
信じていた通りには思い出せず、予測の当たり外れを数えない。外部脳はこの弱点の
補綴器官になれる。

以下の全項目は、NORTH_STAR §7 のプロダクト原則と DESIGN.md §8 非目標を骨格として
維持したまま羽を伸ばす。骨格に抵触する発展（自動診断、ランキング学習、関係タイプ
自動分類、本人以上の理解を主張するシステム）は、どの地平でも採らない。

## 1. 地平 1（1〜2年）— 時間の器官としての完成

### 1.1 予測台帳（Prediction Ledger）

「私は X がこうなると思う（確信度 70%、期日 YYYY-MM）」を記録し、期日に結果と
照合する。健康（「この薬で対象指標は改善するはず」）、仕事、技術予測、投資 —
すべて同じ最小スキーマ（主張・確信度・期日・結果・照合日）に乗る。

- 数年で**自分のキャリブレーション曲線**が得られる:
  「私の『確信 80%』は実際には 60% しか当たらない」という自己知識は実用的である。
- 検証ループ（仮説→時間→結果→改訂）の最小・純粋形。
  第2ドメイン候補 Decisions の前哨戦として H9 の評価材料になる。
- 実装は events YAML パターンの流用で XS〜S。健康ドメインの凍結・依存とは無関係に
  いつでも種を蒔ける。

### 1.2 理解の地層学（belief diff）

`data_snapshots`（DATA_MODEL 設計済み・未実装）を年次で使い「YYYY 年末の理解」を
凍結する。翌年、同じ問いへの snapshot を並べて **diff を取る**。

- 「昨年の私は何を信じ、何が変わり、何が変わらなかったか」が、記憶の改竄を
  経由せずに読める。
- 年次レビューは週次レビューの拡大版ではなく、**この diff の儀式**として設計する。
- 10年後テスト（NORTH_STAR §12）は、毎年の小さな diff の積分として自然に達成される。

### 1.3 供養録（反証された確信のコレクション）

H6 で rejected / superseded になった解釈は削除されず残る。これを年に一度読み返す。

- 成功した結論より、**反証された自分の確信の集合**の方が学習価値が高い。
  系統的な自己バイアス（楽観に倒れる領域、権威に弱い領域）は、個々の誤りではなく
  誤りの集合にしか現れない。
- これはランキング学習（D7 禁止）ではなく、人間が読むための編纂である。
  H6 実装の副産物としてほぼ無償で得られる。

## 2. 地平 2（3〜5年）— 対話の器官へ

### 2.1 「過去の自分」引用モード

build_context_pack の時点フィルタ変種。「2024 年の私はこの問題をどう考えていたか」を、
要約（改竄の入口）ではなく**引用ベースで再構成**する。AI は過去の自分を演じるのでは
なく、過去の記録を法廷の書記のように提示する。反実仮想ではなく証拠。

ここが「本人以上に本人を理解していると主張するシステム」（NORTH_STAR §10）との
分水嶺である。

### 2.2 ソクラテス・モード（良い抵抗）

外部脳が答えを言うのではなく、**矛盾を突きつける**:
「あなたは D5 で関係自動分類を非目標としたが、いま提案している機能はそれに近い。
改訂するのは提案か、Decision か?」

- retrieval + 人間の判断で実装でき、知識グラフの自動生成（D5 禁止）を必要としない。
- AI の生成能力が過剰になる時代、外部脳の最も貴重な出力は「答え」ではなく
  「**良い抵抗**」になる。

### 2.3 認知的独立性の証明機構

AI との共同思考が常態化した世界では、「この理解はどこまで自分のものか」が個人の
知的アイデンティティの問題になる。Cairn は最初から生成物に provenance ラベルを貼り、
原文と合成を構造分離してきた（§6.2）。この規律を貫いた外部脳だけが、10 年後に
「自分の思考の系譜」を証明できる。

**防衛線の明文化が必要**: エージェントが外部脳の原本領域に自分のメモ・要約を
書き込みたがる誘惑は、今後最も破られやすい壁である。原本は人間の活動の記録のみ、
AI 生成物は常にラベル付き・分離領域、の原則を AGENTS.md / NORTH_STAR に恒久条項として
持つ（採否は Decision）。

### 2.4 n=1 科学の器

健康ドメインの observation → intervention → outcome → interpretation は、すでに
自己実験の完全な骨格である。睡眠と判断の質、運動と気分、断酒と検査値 — 因果を
主張しない規律（bounded comparison）のまま、「自分に効くかを自分で確かめる」を
構造化する。医療の平均値エビデンスと個人の応答の間の溝を埋める唯一の材料は
n=1 の縦断データである。

実務的な果実: 主治医交代時の「20 年分の要約 + 根拠」引き継ぎ文書の自動下書き
（visit-brief の拡張、H5 以降）。

### 2.5 分散する読み取り面・一点に留まる原本

読み取り面（レプリカ）は遍在してよいが、書き込み面と原本は一点に留まる —
今日すでに H5-P1（Vault 複製の既定除外 + レポート種別単位の opt-in）で決めた構造の
一般化。全知の単一エージェントを作らず、複数の専門エージェントが bounded MCP で
別の断面だけを見る（minimum disclosure の帰結）。

## 3. 地平 3（10年+）— 思弁

### 3.1 相続可能な外部脳

外部脳は本人の死後どうなるか。家族医療史（observations.subject_id は既に schema に
ある）は子にとって実際の医療価値を持つ。思考の記録は「30 年後テスト」— 子が読める
形で残るか。暗号化とキー相続、「何を残し、何を本人と共に消すか」の遺言的
プロトコル。技術より制度と倫理の問題だが、append-only + provenance はここでも
正しい土台である。

### 3.2 検証の連合（federation）

極めて遠い思弁: 他者の外部脳と「主張と根拠」を交換するプロトコル。SNS が
「結論の交換」で失敗したのに対し、根拠付き・確信度付き・改訂履歴付きの主張交換は
別の力学を持ちうる。個人の Validation loop が社会の Validation infrastructure に
接続する道。Validation Science の社会実装の終着点はここにあるが、本文書の中で
最も不確かな項目である。

### 3.3 忘却の設計

逆方向の羽。記録がある人生は記録に最適化されがちである（グッドハートの法則は
自己記録にも効く）。「完全すぎて使えないアーカイブ」（NORTH_STAR §10）の隣には
「**完全すぎて自由でない人生**」というリスクがある。

- 原本は消さない（append-only）まま、retrieval 層で**意図的に沈殿させる** —
  再浮上しない権利、思い出させない設計。
- pin/mute（backlog X1）の先にあるのは、外部脳が「何を思い出させないか」まで
  本人が統治できること。忘却は欠陥ではなく、設計されるべき機能である。

## 4. 採用基準 — 羽の畳み方

全部はやらない。物差しは一貫して:

> **検証ループを完成させるものが先。生成を増やすだけのものは後。**

| 分類 | 項目 | 接続先 |
|---|---|---|
| 今すぐ種を蒔ける | 1.1 予測台帳 / 1.3 供養録 | plan-2026h2.md の Seeds |
| 設計済み機能の自然な延長 | 1.2 belief diff / 2.1 引用モード / 2.4 n=1 科学 | data_snapshots・context_pack・H2+H6 |
| 文書化だけ先にすべき | 2.3 原本汚染への防衛線 / 3.3 忘却の設計 | Decision Record の将来項目 |
| 思弁として寝かせる | 3.1 相続 / 3.2 連合 | 年次レビューで再訪 |

## 5. 不変の骨格（どの地平でも曲げない）

1. ローカル完結・minimum disclosure（NORTH_STAR §7.7）
2. 原本と合成の構造分離、provenance 第一級（§7.2〜7.4）
3. 重大な結論の最終権限は人間（§7.8）— ソクラテス・モードも re-validation も
   「draft を出す」まで。裁くのは人間
4. 虚偽の確実性への圧縮をしない（§3）— 予測台帳も belief diff も、不確実性を
   不確実性のまま保存する
